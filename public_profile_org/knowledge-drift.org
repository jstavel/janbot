# Knowledge drift — the finite set of decisions you must be able to defend

Use when asked how a team keeps ownership of an AI-assisted codebase, or what
"being substitutable" means in practice. The claim is one sentence: **you are
accountable for a finite set of decisions, not for an unbounded body of
knowledge.**

* The starting point — everyone must be substitutable

Every member of a team has to be replaceable without loss of quality. The AI is
a team member, so the rule applies to it too — and symmetrically to the human
who works with it ([[id:20261018-substitutable-ai][AI must be substitutable — and
so must I]]).

The drift is what erodes that: the layer that **knows** (the model, the
accumulating context, the artifact it generated) separates from the layer that
can **explain and take over** (the humans). Work still ships, so nothing looks
broken.

* The reduction that makes it tractable

"Learning the knowledge of the project" is unbounded — it cannot be closed, and
attempting it is how the attempt dies. The reduction:

| Layer | Size | Closable? |
|-------|------|-----------|
| all knowledge the agent used | unbounded | no |
| the decisions that knowledge produced | **finite, enumerable** | yes |

Accountability attaches to the second row, because **a decision is what binds
the future**. Knowledge that decides nothing is not your responsibility.

* The test — three parts, not one

For each decision:

1. the **decision** — what holds,
2. the **rejected alternative** — what was on the table and lost,
3. the **failure mode** — what breaks if it changes.

*"I know we use a digest"* is half an answer. *"I did not take a tag, because a
tag does not resolve when the container restarts"* is the whole one. **Whoever
does not know the rejected path only knows the outcome — and an outcome can be
copied by imitation.** A missing half = **not verified**.

* The artifact — an index, not a second source of truth

The failure mode of this idea is obvious and fatal: write the decisions down
again and you now have two authorities that will diverge. So the artifact is a
**read model** over the existing single source of truth — the same
command/query split already used for the corpus (`views/` over `objects/`):

> `_bmad-output/` = write model, the authority (ADR = decision, spec = intent)
> `DECISIONS.md` = derived index over it

One row per decision: `id = the ADR's id` (never a new numbering — a second
identity space means a mapping table means drift), the one-line decision, the
rejected alternative, the constraint, the failure mode, blast radius, a **pin**
into the ADR, and one human-owned column: `verified`.

Rules that keep it a read model:

- **no pin, no row** — what cannot be cited is not indexed,
- a decision **without an ADR is not entered**; the hole stays a hole, because
  **the hole is the metric** — an index that fills gaps becomes the write model,
- on conflict **the ADR wins**, and the file says so in its own header,
- regeneration must be idempotent and must **never overwrite `verified`** (the
  frozen-block rule),
- mechanically checkable acceptance criterion: **after regeneration the diff
  touches only the `verified` column.** Anything else changing without a change
  in `_bmad-output` means the index is inventing.

* What is deliberately not in it

- **domain facts** — how a library behaves, syntax; learned on demand, not indexed,
- **rationale prose** — stays in the ADR; the row only points at it,
- **history and revisions of a decision** — that is git and the ADR diff; the
  index shows the state in force,
- **task-level choices and cosmetics** — a variable name is not a decision.

* How it is verified, and how it is sampled

Verification is an **answer produced, not a feeling of recognition**: the agent
takes a row and asks; the human answers in his own words; the answer is graded
against the pinned line — decision, rejected alternative, failure mode — not
against an impression.

Sampling is mechanical, so it never becomes a debate: **must-close blast radius
first, then the longest-unverified, then whatever the agent touched this week**.
Three to five per week; the must-close core cycles permanently, which is correct
— that is the set that has to be answerable at any moment, not once.

* Honest limits

- "Can I defend it" is a **self-assessment mediated by the agent** — better than
  a hunch, still not an objective measurement. Never reported as *proven*.
- The index **ages**: a decision verified six months ago may have changed, which
  is exactly why `verified` carries a date and the must-close core is re-checked.
- No longitudinal evidence yet that the drift actually shrinks. Design, not
  result.
