# AI must be substitutable — and so must I

Use when asked about dependency on AI, about what "expert" means in an agentic
workflow, or why I insist on being able to do the work by hand. The principle is
symmetrical and it is not optional: **if a team member is not substitutable, it
is a single point of failure — and that applies to the agent exactly as it
applies to me.**

* The two-way rule

| Direction | Requirement | Why |
|-----------|-------------|-----|
| AI → team | another agent or a human can take over the AI's part | otherwise the workflow dies with one vendor, one model, one context |
| Human → team | the human can reproduce, debug and extend what was shipped | otherwise the human becomes a rubber stamp on output he cannot verify |

The test is concrete: **turn the AI off**. Can I debug this? Extend it? Fix it?
If the answer is no, the work is not mine yet — it is on loan.

* The honest competence map

Stated without decoration, because the map is the point:

| Technology | Status | Evidence |
|------------|--------|----------|
| Python, Perl, JavaScript | expert — written by hand for years | real delivery across two decades |
| Clojure | deep experience, currently rusty | production work in the past; needs a refresh, not a restart |
| TypeScript | **produced a large project, cannot write a line unaided** | the reactive-testing monorepo was built with agents; the main ideas are understood, the skill is not in the hands |

The TypeScript row is the uncomfortable one and it is recorded as it is: the
project proves the *architecture* was understood and specified, not that the
language is mastered. Without agents the author is a beginner there.

* The strategic choice

Two coherent strategies, and the decision is which one applies when:

- **A — conservative:** apply AI acceleration only to languages where expertise
  already exists (Python, Perl, JavaScript). Guarantees full understanding of
  everything shipped; limits reach.
- **B — expansive:** use AI to enter Clojure or a new stack, **on the condition
  that active personal practice with the language is part of the workflow** —
  not passive acceptance of generated output.

The condition is the whole difference between B and dependency. B without the
practice clause is just A's risk without A's guarantee.

* The self-check I can actually run

The reactive-testing test pipeline, recalled from memory rather than looked up,
as a substitutability drill:

1. write the test in **Gherkin**,
2. fold the Gherkin into the **FSM contracts** model,
3. assign the test to its **test suite**,
4. run it,
5. a **script generates one standalone script per use case** for a developer.

Being able to reconstruct that chain from memory is the kind of evidence that
matters — it shows the method survived the project. The parts that do not come
back from memory are the honest training list.

* Honest limit

The gap is open, not closed. The decision recorded here is a *rule for future
work*, not a claim of current mastery: TypeScript remains a declared gap and
Clojure a refresh task. The rule exists so that the gap cannot quietly grow
while the portfolio looks strong.
