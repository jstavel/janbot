# Insights Health Monitoring — Python metric exporter for a neighboring team

The last project at Red Hat. A neighboring team needed better visibility
into how **Insights Core updates** behave across RHEL versions. This
person built a complete monitoring stack to help them.

**What the stack did:**
- Python `prometheus_client` exporter running on test machines
- Prometheus server collecting metrics from the fleet
- Grafana dashboards for visual monitoring

**Metrics collected:**
- Insights Client: successful/failed uploads, core updates, client/core versions
- GA vs Canary channel comparison
- RHSM system registration status

**Technical highlights:**
- `prometheus_client` metrics (Info, Gauge, Counter, Enum)
- Auto-discovery — any function with `prom_` prefix was automatically registered
- Smart log parsing — section-based strategy (`split_before`) with `more-itertools`
- `funcy` utilities (`@cache`, `@memoize`) for optimization
- TOML configuration via `tomli`
- Node exporter custom metrics for system-level observability

**Development process — spec-driven:**
The entire project was developed using an explicit spec-first workflow:
- `proposal-01/` — analysis.md + proposal.md + specification.md
- `proposal-02/` — brain-dumps.md + specification.md
- `task-01..task-10/` — draft → specification → work-summary → commit
