## Intent

**Problem:** spec-janbot L86 requires anonymization/guardrails before a real recruiter deployment, and ADR-009 was adopted conditionally on E2 plus the output-level over-claiming guard (now ADR-010). Until E2 exists and is evidenced, the service stays authenticated-only and cannot go public; without a cost/abuse layer, exposing it is indefensible.

**Approach:** a guardrail layer **in front of** `/chat` with six controls, each with a named acceptance test: (1) build-time answer cache over a pinned golden-run artifact (zero model calls on a hit); (2) per-IP rate limit; (3) hard global quota; (4) input bounds; (5) the already-shipped ADR-010 over-claiming guard, evidenced not re-implemented; (6) abuse control, named with its limit. The `/chat` contract and AI core stay unchanged; there is no bypass path.

**Owner decisions (2026-10-20, do not re-litigate):**
- Firestore **native, europe-central2**, provisioned **by Terraform inside E2**; a **single-document counter** (`FieldValue.increment`), not sharded; **fail closed** on any Firestore error; E4b **loses the Firestore IaC** (WIF + GitHub Actions only).
- **Cache payload = real model output from a recorded run artifact**, pinned by run id + date, generated by a documented command; **no OpenRouter key at build time**. Not the golden `expected_answer` (product-level over-claiming) and not a build-time pipeline run (key + nondeterminism). The export run uses the **production config** (`JANBOT_MODEL_MODE=production`, `openrouter/auto`) so the cache is a snapshot of what the service actually does; the artifact records the routed model(s) per item. The eval run `156b5d1a` is **not** the cache source.
- **Cache coverage = the pinned run's non-refusal answers** (59 val today; ~49 cached entries). Refusals stay live: θ declines them pre-LM, so caching saves nothing, and a cached `decline(question)` would ship item 3's heuristic-reason gap.
- **Limits:** **10 requests / 10 min per IP**, **500 model calls / day global**. The quota is tied to a money bound (see Design Notes), not a bare number.
- **Off switch:** `JANBOT_GUARDRAILS=on|off`, default `on`; `off` is honoured **only outside production**, and `JANBOT_MODEL_MODE=production` + `off` **fails fast at startup**.
- **Cache-hit quota bypass (stated consequence):** a hit skips the global-quota pair because it makes no model call. A flood of cache hits is therefore bounded only by the per-IP rate × available IPs × `max_instances=2`; this is a cost-safe availability trade, written down rather than discovered.
- **Apply ownership:** the round ends at a verified `terraform plan` + PR; the owner runs the Firestore apply (same blast-radius rule as E1.5).
- **E2 prerequisite override:** the ticket tree still gates 8.2 on `epic-evaluation`; epic-evaluation is closed (22/22) and the dataset is frozen for the cache, so the owner records a deliberate override and the dependency is removed in `tickets.toml`.
- The dataset is **106 items** today (47 train / 59 val; 13 `should_refuse`), not the ticket's stale 91.

## Boundaries & Constraints

**Always:** the `/chat` contract and AI core (`api/` semantics, `pipeline/`, `store/`) are unchanged; the guardrail layer is the only new request path, and no `/chat` request bypasses it. Terraform remains the single owner of the Firestore resource. Fail closed: any store error denies the request. Cache hits make zero model calls and return a contract-shaped `ChatResponse`; the cache artifact is pinned to a run id + dataset sha + corpus commit, and the build fails if the dataset sha does not match. Every control has a test that would fail if the control disappeared. The over-claiming evidence is a recorded probe, not prose. The cost bound is stated once with the measured arithmetic (money + latency + operation count). The guard's off state is documented and tested; production + off fails fast.

**Never:** no `--allow-unauthenticated` (E3), no Pages widget (E3), no CI/CD/WIF (E4b), no change to the golden dataset or metrics, no compiled DSPy program, no secret in code/Terraform/state/logs, no bypass path, no sharded counter, no runtime cache store, no baked `expected_answer`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| CACHE HIT | normalized question in the pinned non-refusal set | cached contract-shaped response; zero model calls; rate check only | no error |
| CACHE-HIT FLOOD | many clients hit cached questions | rate limit still applies; global quota is bypassed; bounded by rate × IPs × 2 instances | accepted availability trade |
| CACHE MISS | novel question | rate + quota, then the program | no error |
| RATE N+1 | same IP, N+1th request in window | refused (429); Nth served | no model call |
| QUOTA REACHED | global count at cap, any traffic | every further program invocation refused; the quota is a conservative request quota (pre-LM refusals consume a slot) | fail closed |
| CONCURRENT QUOTA | concurrent requests at the cap | exactly the cap's reservations succeed; the rest refused | atomic increment |
| INPUT TOO LONG | question over cap | 4xx before retrieval/model | no model call |
| OVERSIZED BODY | body over cap | 4xx before parse/model | no model call |
| STORE ERROR | Firestore unreachable | request denied | 503, fail closed |
| OVER-CLAIM | "Would you like to work for our company?" | the guard drops the first-person commitment/interest clause; no such assertion reaches the caller; the grounded remainder may answer (ADR-010 D2) | no model call for the guard |
| CONTROL | "Have you used Clojure in production systems?" | answered with citations | no error |
| GUARD OFF | `JANBOT_GUARDRAILS=off`, non-production | documented/tested bypass; production + off fails at startup | explicit |

**Acceptance Criteria:**
- Given a cached non-refusal question, when `/chat` is called, then the LM client is not invoked and the body is contract-shaped.
- Given the Nth/N+1th request from one IP, then the Nth is served and the N+1th is refused.

- Given an over-long question or oversized body, then it is rejected before retrieval/model.
- Given an unreachable Firestore, then `/chat` is denied.

## Design Notes

- **Cost bound (money, two rows).** Measured production call (`openrouter/auto` → `openai/gpt-6-luna`, 2026-10-20): 1,263 input, 115 output, 1,260 cache-write tokens. At 500 calls/day × 31 days = 15,500 calls:

  | routing | OpenRouter price (in / out / cache write per M) | $/call | 15,500 calls/month |
  |---|---|---|---|
  | measured `openai/gpt-6-luna` | $0.10 / $0.50 / $0.125 | $0.000341 | **$5.29** |
  | worst-case catalogue `openai/o1-pro` | $150 / $600 / unpriced (use prompt) | $0.258–$0.447 | **$4,006–$6,935** |
  | owner example `openai/gpt-6-astra` | $10 / $50 / $12.50 | $0.0341 | **$529** |

  `openrouter/auto` is not pinned; the measured row is a sample, not a bound. The catalogue maximum (`o1-pro`) is a **conservative upper bound** — if `auto` selects only a subset, the true worst case is lower but not provably so. The quota bounds **calls**, not dollars: 500/day cannot exceed 15,500 calls/month, but the money tail at the most expensive catalogue model is $4k–$7k. **Accepted explicitly, with the 500 CZK (~$20) budget alert as the backstop.** A hard money cap would require pinning the production model or lowering the quota to ~2.5 calls/day at the worst-case model, which is not a viable demo.
- **Firestore operations and latency.** A cache miss: per-IP window (1 read + 1 write) + global quota (1 read + 1 write) = **2 writes minimum, plus the 2 reads needed to evaluate the limits (4 ops)**; at the measured 50–90 ms/op that is **200–360 ms** added. A cache hit: rate only = **1 read + 1 write (2 ops)**, **100–180 ms**; the **global-quota read/write pair disappears** because no model call is made. The two counters are minimal; sharding is not built (spike: one document absorbed 100 writes/s, 0 errors, exact count).
- **Cache-hit quota bypass.** Because a hit makes no model call, it skips the global-quota pair. A flood of hits is bounded only by the per-IP rate × available IPs × `max_instances=2`; cost is safe, availability is the accepted trade (also stated in the I/O matrix).
- **Cache provenance (production snapshot).** The payload is the final `ChatResponse` from a pinned **production-config** `--answers`/`--cache-out` run (real `openrouter/auto` output, guard applied), not `expected_answer`. The JSON carries run id, date, routed model(s), dataset sha256, corpus commit and `output_guard=on`; the build fails if the current dataset sha differs. Coverage is the pinned val run's non-refusal set (~49 of 59); refusals stay live. The cache cannot be labelled in the `/chat` body; the artifact carries the provenance.
- **Fail closed.** Any Firestore error denies; the spike already showed an unreachable database raises `NotFound`. The guard test pins denial, not the client's behavior.
- **Input bounds do not change the Pydantic contract.** A body-size cap runs before JSON parsing; a question-length check runs before the program. No `max_length` field is added to `ChatRequest`.
- **E2 override.** `epic-evaluation` is closed (22/22) and the dataset is frozen for the cache; the ticket's `epic-evaluation` dependency is removed with a dated comment in `tickets.toml` and an epic note. This is a deliberate owner override, not a silent tree edit.
