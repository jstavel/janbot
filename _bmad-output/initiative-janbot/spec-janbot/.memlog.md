- (direction) Prioritize spec-driven development, rigorous verification and test-first quality over vibe coding; deliver a portfolio-grade showcase of modern AI engineering and SDET expertise
- (decision) Use DSPy (not LlamaIndex) as the core RAG pipeline; ChromaDB remains the vector store; OpenRouter for LLM routing. ADR-002 supersedes ADR-001
- (decision) FastAPI is a thin wrapper over the DSPy program; /chat endpoint returns a Pydantic ChatResponse/Citation model, the single source of truth for the JSON contract
- (decision) Two model modes: locked deterministic snapshot (gpt-4o-mini-2024-07-18, temperature 0) for CI/eval; openrouter/auto for production (ADR-004)
- (decision) Milestone 1 testing is pytest + httpx only; TypeScript reactive-testing/Zod harness deferred to Milestone 1.5
- (decision) Clojure orchestrator (Ring/Reitit) deferred to Phase 2 / Milestone 3; independent of the Python AI stack choice (ADR-003)
- (decision) Prompt optimization staged by cost: manual prompt -> BootstrapFewShot -> MIPROv2, each step only if the previous proves the need (ADR-002 addendum)
- (decision) MLFlow tracking introduced only in Milestone 2, not before the pipeline stands
- (constraint) Fail-closed whitelist: the pipeline indexes only public_profile_org/; private notes must never enter ChromaDB
- (constraint) Evaluation determinism: golden dataset and CI run against a locked model snapshot at temperature 0 so metrics are comparable across iterations
- (constraint) Strict separation of the Python AI/vector layer from the test layer (TypeScript via API contracts); the test layer is invariant across all milestones
- (constraint) org-mode chunking must respect subtree hierarchy, PROPERTIES drawers, LOGBOOK and tags; naive text splitters are forbidden
- (constraint) Prompt optimization cost ceiling: manual ~$0.10, BootstrapFewShot ~$0, MIPROv2 $6-15 one-off; each phase only if the previous confirms the need
- (constraint) Pydantic is the single source of truth for the API contract; FastAPI OpenAPI -> codegen Zod for TypeScript, zero drift
- (capability) CAP-1: a recruiter can ask a natural-language question about the owner's professional profile and receive an answer grounded in the owner's public documentation
- (capability) CAP-2: every answer cites the source document(s) it was derived from
- (capability) CAP-3: the service exposes a single /chat HTTP endpoint with a stable, machine-validated JSON contract (answer + citations)
- (capability) CAP-4: only documents under the explicitly designated public profile folder are indexed; private notes are excluded (fail-closed)
- (capability) CAP-5: org-mode hierarchical semantics are preserved during ingestion so answers respect heading structure, properties and tags
- (capability) CAP-6: the system supports two model modes: a locked deterministic snapshot for CI/evaluation and a flexible auto-routed mode for production
- (capability) CAP-7: CI runs automated endpoint tests on every change (pytest + httpx in Milestone 1; TypeScript regression harness in Milestone 1.5)
- (capability) CAP-8: evaluation runs against a golden recruiter Q&A dataset with metrics for retrieval accuracy, citation correctness and hallucination detection, plus cost-staged prompt optimization
- (capability) CAP-9: a future Clojure orchestrator (Ring/Reitit) fronts the Python AI service as the primary API gateway (Phase 2)
- (assumption) The owner maintains personal documentation in org-mode and a public profile corpus lives under public_profile_org/
- (assumption) Anonymization and guardrails are required before real recruiter deployment but are out of scope for Milestone 1
- (question) Which locked model snapshot for CI/eval: openai/gpt-4o-mini-2024-07-18 or anthropic/claude-3.5-sonnet?
- (question) Does an existing public_profile_org/ corpus exist, or must the public profile be assembled before ingestion?
- (question) What is the deployment/hosting target for the FastAPI service and its index?
